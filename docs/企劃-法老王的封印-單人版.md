# 《法老王的封印》

## 單人版遊戲企劃書與 AI 關卡生成規格

> 副標題：太陽之心：法老的試煉
>
> 文件用途：作為後續使用 AI 生成場景、互動物件、謎題流程、對話與關卡程式的共同規格。

---

## 1. 遊戲基本資料

| 項目 | 設定 |
|---|---|
| 遊戲類型 | 古墓探險、密室逃脫、機關解謎、劇情分支 |
| 遊戲平台 | 2D 網頁遊戲 |
| 遊玩人數 | 單人 |
| 開發團隊 | 2 人 |
| 預計遊玩時間 | 約 15 分鐘 |
| 技術方向 | HTML5、CSS、JavaScript、Canvas |
| 遊戲視角 | 2D 橫向卷軸探索；解謎時切換為互動面板 |
| 核心目標 | 解開三道試煉，取得線索，決定是否帶走「太陽之心」 |

### 單人版調整原則

本企劃不設計多人房間、連線同步、角色分工或玩家對玩家互動。所有劇情、謎題與道具都由一名玩家完成；難度透過觀察、線索整合與選擇來形成，而不是透過合作才能解決。

兩人團隊的分工是「一人負責程式與互動，一人負責劇情與視覺」，並不代表遊戲需要兩位玩家連線。

---

## 2. 一句話故事

考古學家亞倫・卡特在埃及金字塔中發現一座從未被記錄的地下墓室，觸發封印後，他必須在古墓崩塌前解開三道試煉，找到「太陽之心」，並在考古發現與守護歷史之間作出選擇。

---

## 3. 遊戲核心體驗

玩家應該感受到以下三個階段：

1. **觀察**：閱讀壁畫、石碑與環境細節。
2. **理解**：將線索轉換成機關操作，找出正確順序或配置。
3. **選擇**：最後決定把寶物帶走，或尊重法老王留下的真正意志。

遊戲不加入戰鬥系統。危險來自倒數計時、錯誤操作、崩塌與錯誤選擇。

---

## 4. 世界觀設定

數千年前，法老王阿蒙拉為了讓王國永遠受到太陽神庇護，命令祭司打造「太陽之心」。它表面上像一顆金色寶石，實際上是控制整座金字塔封印、光線與機關的核心。

阿蒙拉擔心後人只看見寶物的價值，因此命令祭司設下三道試煉：

1. **智慧試煉**：能否理解銘文，而不是只依賴直覺。
2. **秩序試煉**：能否在誘惑面前維持正確秩序。
3. **選擇試煉**：理解太陽之心的真正用途後，是否仍要將它占為己有。

進入墓室後，入口突然關閉，牆上的象形文字逐一亮起。低沉的聲音從墓室深處傳來：

> 「貪婪者將永遠沉睡，理解王之意志者方能重見陽光。」

## 5. 角色設定

### 5.1 主角：亞倫・卡特

- 年齡：32 歲
- 身分：埃及古文明考古學家
- 個性：冷靜、理性、好奇心強
- 能力：擅長辨認古代文字與分析機關
- 弱點：對未知文物過度執著
- 表面目標：找到未被記錄的墓室，完成考古研究
- 內在衝突：研究歷史與個人慾望之間的拉扯

亞倫是唯一可操作角色。玩家的調查行為代表亞倫的研究判斷；玩家最後的選擇也就是亞倫的選擇。

### 5.2 法老王阿蒙拉

- 登場方式：壁畫、石碑文字、幻影與聲音
- 表面形象：守護寶物的古代統治者
- 真正目的：測試進入墓室的人是否會被貪婪控制
- 角色功能：建立試煉規則，並在結局評價亞倫

### 5.3 守墓祭司涅布

- 登場方式：日記、石板紀錄、隱藏暗格與短暫靈魂幻影
- 隱藏秘密：太陽之心不是單純寶石，而是維持金字塔機關的核心
- 角色功能：提供額外線索，讓玩家理解帶走寶物的危險

## 6. 玩家操作與系統

### 6.1 基本操作

| 操作 | 功能 |
|---|---|
| A / D、方向鍵左右 | 移動亞倫 |
| W、上方向鍵、Space | 跳躍；只在場景需要時啟用 |
| E | 調查、閱讀、拿取、操作、繼續對話 |
| B | 開啟或關閉背包 |
| ESC | 關閉目前開啟的解謎面板 |
| 滑鼠點擊 | 點擊解謎石板、鏡子、選項與介面按鈕 |

### 6.2 主要系統

- 2D 橫向卷軸移動
- 靠近互動物件時顯示「E 調查」提示
- 劇情對話框
- 背包與道具描述
- 場景切換
- 三種機關解謎
- 900 秒倒數計時
- 錯誤操作與危險狀態
- 最終選擇與多結局
- 重新開始

### 6.3 遊戲節奏

倒數時間設定為 900 秒。時間不是用來製造高壓操作，而是讓玩家感覺古墓正在失去穩定。

- 900～600 秒：探索與理解線索
- 600～300 秒：操作兩個主要機關
- 300～0 秒：完成光線機關與最終選擇

若玩家在謎題中犯錯，應優先用畫面震動、落沙、聲音與時間扣除提醒危險，而不是立即中斷流程。

## 7. 遊戲狀態與結局旗標

後續製作時，建議把以下資料集中在單人 `gameState` 中：

```js
const gameState = {
  sceneId: 'entrance',
  timeLeft: 900,
  sealActivated: false,
  sunTabletSolved: false,
  sunBadgeObtained: false,
  scaleMistakes: 0,
  priestAmuletFound: false,
  priestRecordRead: false,
  mirrorPuzzleSolved: false,
  sunHeartTaken: false,
  endingId: null
};
```

### 7.1 重要規則

- `sunTabletSolved` 為 `true` 後，才能取得太陽徽章。
- `sunBadgeObtained` 為 `true` 後，太陽徽章可以開啟審判室入口。
- `scaleMistakes >= 2` 時，進入「審判失敗」結局。
- 先閱讀審判壁畫，再於完成天秤前調查底座暗格，才會取得祭司護符並令 `priestAmuletFound = true`。
- 若玩家未發現暗格便先完成天秤，底座會永久封閉，該輪遊戲無法再取得護符。
- 閱讀涅布石板後，`priestRecordRead = true`。
- `mirrorPuzzleSolved` 為 `true` 後，才能進入最後選擇。
- `sunHeartTaken = false` 且三道試煉完成時，進入真結局。
- `sunHeartTaken = true` 且 `priestAmuletFound = true` 時，進入普通過關結局。
- `sunHeartTaken = true` 且沒有護符時，進入「永眠於古墓」結局。
- `timeLeft <= 0` 時，進入「未通過的審判」結局。

## 8. 完整遊戲流程

```text
開始遊戲
  ↓
地下入口：封印啟動、倒數開始
  ↓
場景一：太陽神殿
  調查壁畫與石碑
  完成四石板排序
  取得太陽徽章
  ↓
場景二：天秤審判室
  調查四件物品
  可選：從天秤暗格找到祭司護符與石板紀錄
  完成天秤平衡機關
  ↓
場景三：法老王墓室
  旋轉三面銅鏡
  將光線導向祭壇
  解開太陽之心封印
  ↓
最終選擇：帶走太陽之心 / 留在祭壇
  ↓
依據護符、紀錄、錯誤次數與時間判定結局
```

### 8.1 時間配置

| 階段 | 建議時間 | 主要內容 |
|---|---:|---|
| 開場 | 1 分鐘 | 劇情、封印啟動、倒數開始 |
| 太陽神殿 | 3 分鐘 | 調查線索、完成石板排序 |
| 天秤審判室 | 4 分鐘 | 判斷物品、取得護符、完成天秤 |
| 法老王墓室 | 4 分鐘 | 調整鏡子、解除太陽之心封印 |
| 最終選擇 | 3 分鐘 | 選擇、逃脫或接受法老評價 |

## 9. 劇情腳本與關卡規格

## 9.1 開場：被封閉的入口

### 場景目的

讓玩家知道亞倫孤身受困、古墓已啟動封印，並建立 15 分鐘倒數的理由。

### 畫面與互動

- 場景左側：被沙石掩埋的入口
- 場景中央：刻有太陽圖案的石門
- 場景右側：通往太陽神殿的通道
- 初始玩家位置：石門前
- 玩家必須調查石門，才能觸發封印與開始倒數

### 劇情對話

**亞倫：**

> 這裡沒有出現在任何探勘紀錄裡……牆上的圖案，至少有三千年的歷史。

**互動：調查太陽石門**

**亞倫：**

> 石門上的太陽像是被某種力量鎖住了。這不是普通的墓室入口。

**效果：**入口關閉、沙漏出現、畫面短暫震動。

**古墓的聲音：**

> 古墓封印已啟動。

> 貪婪者將永遠沉睡，理解王之意志者方能重見陽光。

**亞倫：**

> 如果這裡真的有出口，它一定和這些試煉有關。我得往前走。

### AI 關卡生成要求

- 開場不要出現敵人。
- 玩家第一次移動前，讓石門和封印文字成為視覺焦點。
- 倒數計時在調查石門後才開始。
- 入口關閉必須是不可逆事件，不能讓玩家回到外部。

---

## 9.2 場景一：太陽神殿

### 場景目的

教學「觀察 → 閱讀 → 排列 → 獲得道具」的核心循環，並讓玩家理解第一道智慧試煉。

### 場景配置

- 左側：進入通道與古代壁畫
- 中段：石碑與四塊旋轉石板
- 右側：太陽神雕像與尚未開啟的石門
- 地面：少量碎石；不設戰鬥

### 可調查物件

#### 古代壁畫

**提示文字：**

> 壁畫描繪太陽越過天空，聖鷹展翅，甲蟲推動生命，最後河流灌溉大地。

**亞倫：**

> 這不是裝飾，而是一段有順序的敘事。

#### 石碑

石碑顯示完整線索：

> 「太陽升起，聖鷹飛翔，生命甦醒，河流滋養大地。」

**亞倫：**

> 太陽、鷹、甲蟲、尼羅河。這應該就是石板的排列順序。

#### 太陽神雕像

**未解謎時：**

> 雕像的雙手合在胸前，掌心留下了一個徽章形狀的凹槽。

**解謎後：**

> 雕像張開雙手，金色光芒從胸口落下。

### 謎題一：旋轉壁畫機關

#### 石板

1. 太陽
2. 聖鷹
3. 甲蟲
4. 尼羅河

#### 正確順序

```text
太陽 → 鷹 → 甲蟲 → 尼羅河
```

#### 操作方式

- 玩家點擊石板，石板加入目前排列序列。
- 已選石板顯示在上方四個槽位。
- 玩家可以按「清除重排」重新開始。
- 四塊都選完後，系統檢查順序。

#### 失敗效果

- 每次錯誤增加 `sunPuzzleMistakes`。
- 石板震動、落下少量沙石。
- 每次錯誤扣除 15 秒。
- 連續錯誤三次時，額外扣除 30 秒並顯示警告，但仍允許玩家繼續嘗試。

#### 成功效果

- 太陽神雕像張開雙手。
- 玩家取得「太陽徽章」。
- 背包新增道具：

> **太陽徽章**：刻有太陽神眼睛的金色徽章，可以啟動通往審判室的石門。

- 右側石門開啟。

### 成功對話

**古墓的聲音：**

> 第一試煉完成。你看見了文字，也理解了順序。

**亞倫：**

> 這枚徽章不是獎賞。它是下一道門的鑰匙。

## 9.3 場景二：天秤審判室

### 場景目的

讓玩家面對「價值」與「真理」的對比，並提供影響結局的隱藏道具。

### 場景配置

- 左側：入口石門與太陽徽章插槽
- 中央：巨大天秤
- 左下：天秤底座與可調查暗格
- 右側：四個可拿取物品展示台
- 後方牆面：死者接受審判的壁畫

### 可拿取物品

1. 黃金面具
2. 羽毛
3. 石製心臟
4. 寶石聖甲蟲

### 牆面銘文

> 「心若重於真理，靈魂將被黑暗吞噬。」

**亞倫：**

> 羽毛代表真理，心臟代表靈魂。這座天秤要判斷的不是金子的重量。

### 隱藏物件：祭司護符

壁畫底部另刻著：「審判既定，秤座永閉。守墓者的印記，藏於真理之下。」

玩家讀過壁畫後，在完成天秤前再次調查底座，會發現一個被灰塵遮住的暗格。若玩家跳過壁畫、直接完成天秤，底座接縫會隨審判鎖死，該輪遊戲無法再取得其中的護符。

**涅布的石板紀錄：**

> 寶物離開祭壇之時，死亡之門將會開啟。唯有守墓者的護符，能讓持有者穿越崩塌的通道。

**亞倫：**

> 涅布早就知道有人會試圖帶走太陽之心。他留下這枚護符，是為了讓那個人還有一次回頭的機會。

取得後：

- `priestAmuletFound = true`
- 背包新增「祭司護符」
- 若玩家再次調查暗格，顯示「暗格已經空了」。
- 未取得護符不會阻止玩家進入或完成第三場景，但帶走太陽之心時將失去逃生保護。

### 謎題二：天秤重量機關

#### 正確配置

```text
左盤：石製心臟
右盤：羽毛
黃金面具與寶石聖甲蟲：不可放入天秤
```

#### 操作方式

- 玩家靠近物品後按 E 拿取。
- 手上持有物品時，靠近天秤左盤或右盤會顯示放置提示。
- 玩家可以取回已放置物品。
- 正確配置後，天秤保持水平，右側石門開啟。

#### 錯誤操作

- 將黃金面具或寶石聖甲蟲放上任一盤，觸發飛箭陷阱。
- 畫面震動、扣除 20 秒、`scaleMistakes += 1`。
- 累積兩次錯誤後立即進入「審判失敗」結局。

#### 成功對話

**古墓的聲音：**

> 第二試煉完成。你沒有用黃金衡量靈魂。

**亞倫：**

> 真正的重量，從來不在物品本身，而在我們賦予它的價值。

---

## 9.4 場景三：法老王的墓室

### 場景目的

完成最後的操作型機關，揭露太陽之心的真實用途，讓玩家進入最終選擇。

### 場景配置

- 左側：通往審判室的入口
- 中央：三面可旋轉銅鏡
- 左後方：太陽石柱
- 右後方：月亮石柱
- 最右側：封印祭壇與漂浮的太陽之心
- 下方：即將崩裂的地面

### 進入對話

**法老王幻影：**

> 你已經走到王的最後一扇門前。現在，讓光線回答你的問題。

**亞倫：**

> 太陽之心不是被藏起來，而是被連接在整座墓室的機關裡。

### 謎題三：光線反射機關

#### 目標

將入口射入的光線依序反射至：

1. 左側太陽石柱
2. 右側月亮石柱
3. 中央祭壇

#### 操作方式

- 玩家點擊三面銅鏡，使每面鏡子順時針旋轉 90 度。
- 每次旋轉立即顯示光線路徑。
- 正確狀態建議設定為：

```text
鏡一：向左
鏡二：直行，將光線送往中央王座
鏡三：向右
```

- 如果玩家已閱讀涅布石板，背景會短暫出現「光必須經過日與月，才能觸及核心」的提示。
- 三面鏡子正確後，祭壇封印解除。

#### 失敗效果

- 光線中斷，銅鏡發出刺耳聲音。
- 每次錯誤扣除 10 秒。
- 不直接結束遊戲，讓玩家能透過光線路徑修正。

#### 成功效果

- 太陽石柱與月亮石柱同時亮起。
- 光線集中至太陽之心。
- 出口開啟，但寶物仍等待玩家選擇。

**法老王幻影：**

> 最後的試煉不是打開封印，而是決定封印之後，你要成為什麼樣的人。

---

## 10. 最終選擇與劇情分支

玩家完成第三道機關後，右側祭壇的束縛會鬆開，但只要太陽之心尚未被取走，場景仍維持有太陽之心的封印祭壇外觀。玩家必須走到最右側調查祭壇，聽完亞倫的短對話後才會顯示兩個選項；選擇取走後才換成空祭壇，選擇留下則維持原貌。過程不另外開啟大型祭壇 CG，中央王座也只負責護符與光路機關，不會重複觸發最終選擇：

1. **取下太陽之心**
2. **將太陽之心留在祭壇**

玩家必須點擊選項或使用方向鍵加 E 確認。

完成選擇後，結局採用與序章相同的分段淡入畫面；文字播放期間可略過動畫，但略過不會跳過結局結果。結局文字顯示完成後自動淡出並回到既有遊戲主頁，不重新初始化 Canvas 或遊戲迴圈；最終失敗結局在返回主頁前仍可選擇回到最近場景紀錄。

### 10.1 選擇「將太陽之心留在祭壇」

**亞倫：**

> 我會記錄它，但不會帶走它。這不是屬於我的寶物。

**法老王：**

> 真正的寶藏，並非黃金，而是理解歷史的智慧。

若三道機關完成，玩家進入：

> **TRUE END：歷史的守護者**

### 10.2 選擇「取下太陽之心」

**亞倫：**

> 這項發現足以改寫整個考古學界。我不能把它留在黑暗裡。

太陽之心離開祭壇後，金字塔失去能源，古墓開始崩塌。

#### 有祭司護符

護符發出保護光芒，玩家進入逃脫流程。

**涅布的聲音：**

> 你選擇帶走它，至少記得它曾經保護過你。

玩家成功離開墓室，進入：

> **NORMAL END：被帶走的封印**

最後畫面：太陽之心被放入現代博物館展示櫃，夜裡再次發出金色光芒。

#### 沒有祭司護符

出口被落石封鎖，亞倫被困在墓室中。

**法老王的聲音：**

> 又一位被黃金蒙蔽雙眼的人。

玩家進入：

> **BAD END：永眠於古墓**

## 12. AI 關卡生成規格

後續請 AI 生成關卡時，必須遵守以下限制：

### 12.1 全域限制

- 遊戲只有一名玩家角色：亞倫・卡特。
- 不加入第二名可操作角色。
- 不加入多人房間、連線同步或合作專屬機關。
- 不加入戰鬥、技能樹或複雜 NPC 任務。
- 每個場景最多 4～6 個主要互動物件。
- 每個謎題必須可以由玩家在同一場景內找到線索並完成。
- 所有重要線索至少提供兩種取得方式：閱讀文字與觀察畫面。
- 失敗後不能讓玩家卡死；除最終失敗結局外，謎題都必須可以重試。
- 互動物件需要顯示清楚的名稱、提示與目前狀態。

### 12.2 AI 生成單一關卡時的輸出格式

請 AI 依照以下欄位輸出：

1. 關卡名稱與故事目的
2. 玩家進入條件
3. 場景視覺描述
4. 橫向場景布局：左、中、右區域
5. 玩家出生點與出口位置
6. 可調查物件清單
7. 每個物件的互動提示、調查文字與觸發條件
8. 謎題規則與正確答案
9. 錯誤操作效果
10. 解謎成功效果
11. 道具取得與使用方式
12. 對話腳本
13. 進入下一場景的條件
14. 需要寫入的 `gameState` 旗標
15. 無障礙與操作提示

### 12.3 可複製的 AI 關卡生成 Prompt

```text
你是一名 2D 網頁密室逃脫遊戲關卡設計師。

請為《法老王的封印》設計一個單人可遊玩的關卡。

遊戲設定：
- 玩家角色：考古學家亞倫・卡特
- 遊戲類型：古墓探險、機關解謎、劇情分支
- 平台：HTML5 Canvas + CSS + JavaScript
- 遊玩時間：整體約 15 分鐘
- 本關時間：3～5 分鐘
- 操作：左右移動、E 互動、B 背包、滑鼠點擊機關
- 不使用多人連線、不使用戰鬥、不加入第二名玩家角色

請輸出：
1. 關卡名稱
2. 本關故事目的
3. 場景氛圍與色彩
4. 橫向卷軸布局，分成左側、中段、右側
5. 玩家出生點、出口與碰撞區域
6. 4～6 個可互動物件
7. 每個互動物件的名稱、距離、E 提示、調查文字
8. 一個可以靠場景線索解開的謎題
9. 謎題的正確答案、錯誤效果、重試方式
10. 成功後的動畫、音效與道具獎勵
11. 10～15 句繁體中文劇情對話
12. 進入下一關的條件
13. gameState 需要新增或修改的欄位
14. 可直接交給前端工程師實作的事件流程
15. 手機與桌面瀏覽器的操作提示

設計要求：
- 線索必須公平，玩家不需要猜作者心情。
- 重要答案至少透過文字和畫面各提示一次。
- 不能因一次錯誤就直接結束遊戲。
- 對話要短，優先讓玩家操作與探索。
- 不要使用現代 UI 語言，維持神秘、古老、金色光芒的古埃及風格。
```

## 13. AI 生成關卡程式時的資料格式

後續若要讓 AI 直接生成 JavaScript，可以要求它以以下資料結構描述互動物件：

```js
const levelObjects = [
  {
    id: 'priest_record',
    type: 'inspectable',
    sceneId: 'judgement_room',
    x: 420,
    y: 360,
    width: 90,
    height: 120,
    prompt: '調查天秤底座',
    dialogue: '暗格裡藏著涅布留下的石板紀錄。',
    grants: ['priestRecordRead', 'priestAmuletFound'],
    oneTime: true
  }
];
```

每個謎題至少需要定義：

```js
const puzzleDefinition = {
  id: 'scale_trial',
  sceneId: 'judgement_room',
  solution: {
    left: 'stone_heart',
    right: 'feather'
  },
  failLimit: 2,
  onWrong: 'triggerScaleTrap',
  onSolved: 'openTombChamber'
};
```
