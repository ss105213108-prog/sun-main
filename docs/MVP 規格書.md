# **《太陽之心：法老的試煉》MVP 最小可行性產品規格書 (Minimum Viable Product)**

## **1\. MVP 核心目標與驗證假設**

* **核心假設**：玩家能在 2D 網頁環境下，透過「點擊調查 \+ 背包道具 \+ 機關解謎」獲得具沉浸感的密室逃脫體驗。  
* **MVP 目標**：以最精簡的資源與開發週期（1-2 週），完成一個可跑通「開場 ➔ 3場景探索 ➔ 3機關破解 ➔ 多結局」的完全可遊玩 Prototype。

## **2\. MVP 功能範疇 (In-Scope vs. Out-of-Scope)**

| 功能模組 | MVP 必須包含 (In-Scope) | 暫不納入 MVP (Out-of-Scope) |
| :---- | :---- | :---- |
| **頁面與場景** | • 單頁面應用 (SPA) • 3 個主要場景（神殿、審判室、墓室） | • 獨立的預告頁/營運網站 • 複雜的動態鏡頭運鏡 |
| **互動與控制** | • 滑鼠點擊熱點 (Hotspot) • 基本提示訊息（文字彈窗） | • 拖曳式物理互動 • 複合式組合道具系統 |
| **核心機關** | • 機關1：石板排序（密碼型） • 機關2：天秤重量（數值平衡） • 機關3：光線反射（開關切換） | • 限時極限機關 • 動作類微遊戲 (Minigames) |
| **道具系統** | • 背包列（上限 5 格） • 道具點擊選取與使用 | • 道具放大檢視 (3D/2D Detail view) • 道具合成機制 |
| **劇情與結局** | • 文字對話框（主主角亞倫對白） • 關鍵分歧點（影響 2 種結局：True / Bad） | • 全配音 (CV) • 複雜動態 CG 動畫 • 3 種以上的衍生結局 |
| **資料與系統** | • 單次遊玩狀態記錄（In-Memory） • 遊戲重置按鈕 | • 雲端存檔 • 排行榜 / 成就系統 |

## **3\. 核心遊戲循環 (Core Loop)**

\[開場劇情\] ➔ \[場景 1：太陽神殿 (搜集道具 / 破解石板)\]   
           ➔ \[場景 2：天秤審判室 (天秤平衡)\]   
           ➔ \[場景 3：法老王墓室 (光線反射 \+ 最終選擇)\]   
           ➔ \[結局判定 (True End / Bad End)\]

## **4\. MVP 機關實作簡化邏輯**

### **機關 1：石板排序 (太陽神殿)**

* **邏輯**：畫面顯示 4 塊圖騰石板，點擊可更換順序，順序正確觸發通往場景 2 的門。  
* **判定**：陣列匹配（例如：\[3, 1, 4, 2\]）。

### **機關 2：天秤重量 (審判室)**

* **邏輯**：玩家將搜集到的「羽毛」與「砝碼」放入天秤兩端，使天秤達到平衡。  
* **判定**：左側重量 \== 右側重量 時過關，獲得「太陽金卡」。

### **機關 3：光線反射 (墓室)**

* **邏輯**：3 個反射鏡，點擊旋轉角度（0° / 90° / 180° / 270°），使光線導向法老胸口的寶石。  
* **判定**：鏡頭角度組合符合解（例如：\[90, 180, 270\]）。

## **5\. MVP 驗收標準 (Acceptance Criteria)**

1. **流暢性**：玩家能在 15 分鐘內無 Bug 跑通完整流程。  
2. **操作性**：所有熱點與道具皆能透過點擊正確觸發與消耗。  
3. **分歧驗證**：墓室選擇「取走寶石」觸發 Bad End；選擇「放下獻祭」觸發 True End。  
4. **相容性**：支援主流瀏覽器（Chrome / Safari / Edge）桌面端正常顯示。
